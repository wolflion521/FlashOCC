

# 自动驾驶3D Occupancy感知算法全景解析

## 1. 核心流程：从输入到输出

### 1.1 输入模态 (Input Modality)：数据的起点

输入模态是自动驾驶3D Occupancy感知算法的基石，它决定了系统所能获取的环境信息的类型、质量和维度。不同的传感器模态具有各自独特的优势和局限性，因此，算法的设计往往围绕着如何处理特定模态的数据展开。例如，以激光雷达（LiDAR）为中心的算法依赖于精确但稀疏的点云数据，而以视觉（相机）为中心的算法则需要从2D图像中推断出3D几何信息。多模态融合算法则试图结合不同传感器的优点，以实现更鲁棒、更全面的环境感知。选择合适的输入模态不仅影响数据预处理的复杂性，还直接关系到后续网络架构、视图表示和信息融合策略的设计。例如，视觉中心方法必须解决从2D到3D的视图转换问题，而LiDAR中心方法则需要处理点云的稀疏性并将其转换为密集的表示形式。因此，在分析任何Occupancy感知算法时，首要任务是明确其核心的输入模态，这为理解整个算法的流程和权衡提供了关键的上下文。

#### 1.1.1 视觉中心 (Vision-Centric)

视觉中心（Vision-Centric）的3D Occupancy感知算法完全依赖于相机捕获的图像数据来重建和理解三维环境。这类方法的核心挑战在于如何从二维图像中恢复出精确的三维几何结构和语义信息。由于相机本身无法直接测量深度，算法必须依赖于单目或立体视觉技术来推断距离。单目方法通常利用深度学习模型从单张图像中学习深度线索，而立体方法则通过匹配左右相机图像中的对应点来计算视差，从而得到深度图。视觉中心方法的优势在于成本相对较低，且能够提供丰富的纹理和颜色信息，这对于语义理解至关重要。然而，它们对光照变化、天气条件（如雨、雪、雾）和物体遮挡非常敏感，并且在无纹理区域或远距离物体的深度估计上往往表现不佳。典型的视觉中心算法，如**MonoScene**和**TPVFormer**，通过精巧的网络设计，如使用Transformer架构和特定的视图表示（如三视图TPV），来弥补深度信息缺失带来的挑战，从而在Occupancy预测任务上取得了显著进展 。

##### 1.1.1.1 相机配置 (Camera Setup)

在视觉中心的Occupancy感知中，相机的配置是决定系统性能的关键因素之一。不同的相机配置提供了不同层次的几何信息和视野覆盖范围。**单目（Monocular）** 配置是最简单和成本最低的方案，它仅使用一个相机。单目方法依赖于从单张图像中学习深度和几何线索，这通常是一个不适定问题（ill-posed problem），因为存在尺度模糊性。为了解决这个问题，单目算法通常需要结合大量的训练数据和复杂的网络架构，例如通过预测深度分布或利用几何约束来辅助3D重建。**多相机（Multi-Camera）** 或环视相机系统，通常由六个或更多相机组成，覆盖车辆周围的360度视野。这种配置能够提供全方位的环境感知，有效消除单相机的视野盲区。多相机系统面临的挑战是如何将来自不同视角的图像特征有效地融合到一个统一的3D表示中，这需要精确的相机标定和鲁棒的视图转换与融合机制。**立体（Stereo）** 相机配置使用两个或多个相机，通过三角测量原理计算视差图，从而直接获得深度信息。相比于单目系统，立体视觉在深度估计的精度上具有天然优势，尤其是在近距离和纹理丰富的区域。然而，立体匹配算法在弱纹理、重复纹理或遮挡区域仍然面临挑战，且其有效测量范围受限于基线长度。

##### 1.1.1.2 图像类型 (Image Type)

视觉中心算法处理的图像类型主要分为**RGB**和**RGB-D**两种。绝大多数方法，如**TPVFormer**和**SurroundOcc**，主要处理标准的RGB图像 。RGB图像提供了丰富的颜色、纹理和语义信息，是进行场景理解和物体分类的基础。算法需要从这些2D图像中推断出3D几何结构，这通常通过深度学习模型学习隐式的深度表示来实现。为了增强几何感知能力，一些方法会显式地预测深度图，并将深度信息作为额外的输入或监督信号。例如，**FB-OCC**等方法就利用了深度信息来辅助视图转换过程 。**RGB-D**图像则是在RGB图像的基础上，为每个像素附加了一个深度值，形成了一个四通道的输入。深度信息可以直接从RGB-D传感器（如Kinect）或通过立体视觉算法获得。使用RGB-D图像可以显著简化3D重建的难度，因为深度信息是直接可用的。然而，在自动驾驶场景中，由于室外环境光照变化剧烈且测量距离有限，RGB-D传感器的应用受到限制。因此，大多数自动驾驶的Occupancy算法仍然以RGB图像为主要输入，并通过网络内部机制来学习和利用深度信息。

##### 1.1.1.3 时间输入 (Temporal Input)

时间输入的处理方式对视觉中心算法的动态感知能力至关重要。**单帧（Single-Frame）** 输入是最基本的设置，算法仅处理当前时刻的图像来预测Occupancy。这种方法计算效率高，但无法利用时序信息来增强预测的鲁棒性和准确性，例如通过多帧观测来消除瞬时遮挡或噪声的影响。许多早期的Occupancy预测方法，如**MonoScene**，主要基于单帧输入 。**多帧（Multi-Frame）** 输入则允许模型利用历史信息。通过融合连续多帧的图像特征，模型可以更好地理解场景的动态变化，例如识别和跟踪移动的物体，或者通过时间积分来增强对静态结构的感知。处理多帧输入的方法多种多样，包括使用3D卷积、循环神经网络（RNN）或时序注意力机制。例如，一些方法会维护一个时序特征队列，并通过注意力机制来融合不同帧的特征，从而赋予模型“记忆”能力。这种时序建模对于预测动态Occupancy（如Occupancy Flow）至关重要，能够帮助自动驾驶系统更好地预判未来环境的变化，从而做出更安全的决策。

#### 1.1.2 激光雷达中心 (LiDAR-Centric)

激光雷达（LiDAR）中心的3D Occupancy感知算法直接处理由LiDAR传感器生成的点云数据。与视觉中心方法相比，LiDAR能够提供精确、直接的3D几何测量，包括距离、方位角和高度信息，因此在几何精度上具有无与伦比的优势。LiDAR点云本质上是稀疏的，尤其是在远距离区域，这要求算法具备从稀疏数据中重建出密集、完整的3D场景的能力。LiDAR中心方法通常对天气和光照变化不那么敏感，能够在夜间或恶劣天气条件下稳定工作。然而，LiDAR数据缺乏颜色和纹理信息，这使得纯粹的语义分割任务更具挑战性。此外，LiDAR传感器成本高昂，且其机械旋转部件可能存在可靠性问题。典型的LiDAR中心算法，如**LMSCNet**，通常采用稀疏卷积（Sparse Convolution）等高效操作来处理点云数据，并将其转换为体素（Voxel）或柱状（Pillar）等结构化表示，以便应用标准的3D卷积神经网络进行处理。

##### 1.1.2.1 点云密度 (Point Cloud Density)

LiDAR点云的密度是影响算法设计和性能的关键因素，通常分为**稀疏（Sparse）** 和**密集（Dense）** 两类。**稀疏点云**是大多数自动驾驶场景中LiDAR数据的常态，尤其是在使用低线束（如16线、32线）LiDAR或探测远距离物体时。点云的稀疏性意味着大量的3D空间区域是空的，没有直接的测量点。这给Occupancy预测带来了挑战，因为算法需要从这些不完整的观测中“脑补”出整个场景的几何结构。为了应对稀疏性，研究人员开发了多种技术，如稀疏卷积（Sparse Convolution），它只对非空体素进行计算，从而大大提高了计算效率。此外，一些方法通过累积多帧点云来增加点云密度，或者利用深度学习模型学习从稀疏到密集的映射。**密集点云**通常通过高线束（如64线、128线）LiDAR或在近距离区域获得。密集点云提供了更丰富的几何细节，使得场景重建和物体识别变得更加容易。然而，处理密集点云需要更高的计算和内存开销。算法需要在精度和效率之间做出权衡，例如通过下采样或采用分层处理策略来管理数据量。

##### 1.1.2.2 时间输入 (Temporal Input)

与视觉中心方法类似，LiDAR中心算法也可以利用时间信息来提升性能。**单次扫描（Single-Sweep）** 输入指的是算法仅处理当前时刻LiDAR传感器旋转一周所采集到的点云数据。这种方法的优点是数据量相对较小，处理速度快，能够实时响应环境变化。然而，单次扫描的点云非常稀疏，尤其是在远距离和非水平方向上，这限制了场景重建的完整性和准确性。为了克服单次扫描的局限性，**多次扫描（Multi-Sweep）** 输入被广泛应用。该方法通过将连续多个时刻（例如过去0.5秒或1秒）的点云数据，根据车辆的位姿（由GPS/IMU提供）进行对齐和累积，从而生成一个密度更高、信息更丰富的点云。累积后的点云能够更好地描绘出静态环境结构，并有助于更准确地分割和识别动态物体。例如，**Occ4cast**等方法就是基于多帧LiDAR点云进行4D Occupancy的补全和预测 。处理多次扫描数据需要更复杂的网络架构，以有效融合时序信息并处理由车辆自身运动带来的点云畸变。

#### 1.1.3 多模态 (Multi-Modal)

多模态（Multi-Modal）3D Occupancy感知算法旨在融合来自不同传感器（如相机、LiDAR、Radar）的数据，以克服单一模态的固有局限性，实现更鲁棒、更全面的环境感知。这种融合的核心思想是“取长补短”：利用LiDAR的精确几何信息、相机的丰富语义和纹理信息，以及Radar在恶劣天气下的穿透能力和速度测量能力。多模态融合可以在不同层面进行，包括数据层（早期融合）、特征层（中期融合）和决策层（晚期融合）。例如，**FusionOcc**和**OccFusion**等方法通过在2D和3D空间中进行特征融合，将LiDAR的深度信息与相机的语义信息相结合，从而在Occ3D-nuScenes等基准上取得了领先的性能 。多模态系统的设计挑战在于如何处理不同模态数据之间的异构性（如数据格式、分辨率、视角差异）和异步性，以及如何设计有效的融合机制来动态地权衡不同信息源的重要性。

##### 1.1.3.1 模态组合 (Modality Combination)

多模态Occupancy感知中常见的传感器组合包括**Camera + LiDAR**、**Camera + Radar**、**Camera + LiDAR + Radar**等。**Camera + LiDAR**是最主流的组合，它结合了相机的低成本、高分辨率和LiDAR的高精度几何测量。这种组合在许多公开数据集（如nuScenes、Waymo）和算法（如**OpenOccupancy**、**FusionOcc**）中得到了广泛应用 。融合策略通常涉及将图像特征通过视图转换投影到3D空间（如BEV），然后与LiDAR的体素化特征进行对齐和融合。**Camera + Radar**组合则是一种更具成本效益的方案，尤其适用于对恶劣天气鲁棒性要求高的场景。Radar能够提供目标的距离和径向速度信息，且不受光照和天气影响，可以作为相机在恶劣条件下的有效补充。然而，Radar的分辨率较低，且存在大量杂波，如何有效地将其与图像特征融合是一个研究热点。**Camera + LiDAR + Radar**的三模态融合是追求极致鲁棒性和准确性的方案。通过融合三种传感器的信息，系统可以在各种复杂环境下（包括恶劣天气、传感器部分失效等）保持可靠的感知能力。这种组合的设计复杂度最高，需要精巧的融合架构来处理三种异构数据源。此外，一些前沿研究还探索了融合文本（Text）信息，例如通过自然语言指令来引导Occupancy感知，这为自动驾驶系统的人机交互和场景理解开辟了新的可能性。

### 1.2 视图表示 (View Representation)：特征的载体

视图表示是3D Occupancy感知算法中的一个核心概念，它定义了算法在内部如何组织和处理从原始传感器数据中提取的特征。选择合适的视图表示对于平衡模型的性能、计算效率和内存消耗至关重要。不同的表示方法对几何信息的保留程度、对网络架构的友好性以及与下游任务的兼容性都有显著影响。例如，**体素化（Volumetric）** 表示能够完整地保留3D空间信息，但计算和内存开销巨大；而**鸟瞰图（BEV）** 表示通过将3D信息压缩到2D平面，极大地提高了计算效率，成为当前工业界和学术界的主流选择。**三视图（TPV）** 表示则试图在体素和BEV之间找到一个折衷，通过三个正交平面来更全面地刻画3D场景。算法的设计，特别是编码器-解码器结构和视图转换模块，都紧密围绕着所选的视图表示来展开。因此，理解不同视图表示的优缺点及其适用场景，是深入分析Occupancy算法的关键。

#### 1.2.1 体素化 (Volumetric)

体素化（Volumetric）表示是将3D空间划分为一个由立方体单元（即体素，Voxel）组成的规则网格。每个体素可以存储其是否被占据（Occupancy）以及对应的语义标签（Semantic Label）。这种表示方法最直接地保留了3D场景的几何和拓扑结构，因为它是一个完整的3D体积表示。体素化表示的优点在于其直观性和完备性，能够精确地表示任意复杂的3D形状。然而，其最大的缺点是计算和内存效率低下。对于一个固定大小的3D空间，体素网格的分辨率越高，所需的内存和计算量就呈立方级增长。为了缓解这个问题，研究人员提出了多种优化策略，如使用**稀疏卷积（Sparse Convolution）** 来跳过对空体素的计算，或者采用**八叉树（Octree）** 等自适应数据结构来在细节丰富的区域使用高分辨率，在平坦区域使用低分辨率。典型的基于体素化表示的算法包括**MonoScene**，它直接将图像特征投影到一个3D体素网格中进行处理 。

##### 1.2.1.1 坐标系 (Coordinate System)

在体素化表示中，坐标系的选择对特征的几何保真度和计算效率有重要影响。最常见的坐标系是**欧几里得坐标系（Euclidean, XYZ）** ，它将3D空间划分为规则的立方体网格。这种表示简单直观，与标准的3D卷积操作兼容性好。然而，在处理LiDAR点云时，由于点云的分布通常是不均匀的（在传感器附近密集，在远处稀疏），使用固定的立方体网格会导致近处体素过于密集而远处体素过于稀疏，造成计算资源的浪费。为了解决这个问题，**圆柱坐标系（Cylindrical）** 被提出。圆柱坐标系将空间划分为径向、角度和高度三个维度，其划分方式与LiDAR的扫描模式（旋转扫描）更为匹配。例如，**OccCylindrical**框架就采用了圆柱坐标系来处理多模态数据，认为这种表示能更好地保留每个传感器模态的细粒度几何信息 。在圆柱坐标系下，点云在径向上的分布更为均匀，有助于更有效地提取特征。

##### 1.2.1.2 体素类型 (Voxel Type)

根据体素的形状和排列方式，体素化表示可以分为几种不同的类型。**立方体（Cubic）** 体素是最标准和最常见的形式，它将空间划分为规则的立方体网格。这种表示与3D卷积核的形状完美匹配，便于实现。**柱状（Pillar）** 体素是一种变体，它在水平方向（X-Y平面）上保持高分辨率，而在垂直方向（Z轴）上则覆盖整个高度范围，形成一个细长的柱体。这种表示常用于将点云转换为BEV特征图，例如**PointPillars**算法。它将每个Pillar内的点云特征进行聚合，从而在BEV平面上生成一个伪图像，然后可以使用高效的2D CNN进行处理。**圆柱形（Cylindrical）** 体素则是在圆柱坐标系下定义的，其形状为扇形柱体。这种体素类型特别适合处理LiDAR点云，因为它能更好地匹配点云的径向分布特性，从而在保持几何信息的同时提高计算效率 。

##### 1.2.1.3 分辨率策略 (Resolution Strategy)

体素网格的分辨率直接决定了3D场景表示的精细程度，同时也极大地影响着计算成本。因此，采用合适的分辨率策略至关重要。**固定分辨率（Fixed）** 是最简单的方法，即在整个3D空间中使用统一的体素大小。这种方法实现简单，但如前所述，对于非均匀分布的点云数据效率不高。**自适应分辨率（Adaptive）** 策略则试图根据场景的复杂程度动态调整体素的大小。例如，在物体边界或细节丰富的区域使用高分辨率体素，而在平坦或空旷的区域使用低分辨率体素。八叉树（Octree）是实现自适应分辨率的一种常用数据结构。**多尺度（Multi-Scale）** 策略则通过构建一个特征金字塔来处理不同尺度的信息。网络在不同分辨率的体素网格上提取特征，然后将这些多尺度特征进行融合，从而获得既有局部细节又有全局上下文的表示。这种策略有助于网络同时识别小物体和理解大场景结构。

#### 1.2.2 鸟瞰图 (BEV)

鸟瞰图（Bird's-Eye-View, BEV）表示是当前3D Occupancy感知领域，尤其是视觉中心方法中，最受欢迎和最有效的视图表示之一。BEV的核心思想是将3D空间的信息投影到一个与地面平行的2D平面上。这种表示方法极大地简化了计算，因为处理2D特征图比处理3D体素网格要高效得多。BEV表示天然地与许多下游任务（如路径规划、运动预测）的输入格式兼容，因为这些任务通常在BEV平面上进行。在BEV表示中，高度（Z轴）信息通常被编码到特征图的通道维度中。例如，可以将不同高度范围的体素特征拼接（concatenate）在一起，形成一个多通道的BEV特征图。典型的BEV-based算法，如**BEVFormer**和**LMSCNet**，通过精巧的视图转换模块（如基于交叉注意力的转换）将多相机图像特征统一到一个BEV空间，然后在这个空间中进行后续的感知任务 。

##### 1.2.2.1 高度编码 (Height Encoding)

在BEV表示中，如何处理和编码高度信息是一个关键问题。由于BEV是一个2D平面，原始的3D高度信息必须被转换到2D特征图的通道维度中。一种常见的方法是**通道维度编码（Channel Dimension）** ，即将3D空间在垂直方向上划分为多个“桶”（bins），每个桶对应BEV特征图的一个通道。例如，可以将-2米到2米的高度范围划分为8个桶，每个桶的宽度为0.5米。然后，将落入每个桶内的3D特征（如来自体素或点云的特征）进行池化或聚合，作为该通道的特征值。这种方法简单有效，能够保留一定的高度信息。另一种方法是**显式Z轴（Explicit Z-Axis）** ，虽然最终输出是BEV，但在网络内部仍然保留一个显式的Z维度来处理特征，直到最后的输出阶段才将其压缩到BEV平面。例如，一些方法会先构建一个3D体素特征，然后通过一个垂直方向的卷积或MLP将其压缩成一个BEV特征图。

##### 1.2.2.2 特征压缩 (Feature Compression)

将3D特征压缩到2D BEV平面需要进行特征压缩。这个过程的目标是在尽可能保留关键信息的同时，减少数据维度。**垂直池化（Vertical Pooling）** 是最直接的方法，即在每个BEV网格位置，对该位置垂直方向上的所有体素或点云特征进行池化操作（如最大池化或平均池化）。这种方法计算高效，但可能会丢失一些细粒度的高度信息。**MLP投影（MLP Projection）** 则是一种更灵活的方法。对于每个BEV网格，将垂直方向上的所有特征向量作为输入，通过一个多层感知机（MLP）来生成一个聚合的BEV特征向量。MLP可以学习到一个更复杂的非线性映射，从而可能比简单的池化操作保留更多信息。例如，BEVFormer中的BEV查询（BEV Queries）就是通过交叉注意力机制与多相机图像特征进行交互，从而隐式地完成了特征的聚合和压缩。

#### 1.2.3 三视图 (TPV)

三视图（Tri-Perspective-View, TPV）表示是一种相对较新的视图表示方法，它试图在体素表示的完备性和BEV表示的高效性之间找到一个平衡点。TPV表示的核心思想是，一个3D场景可以通过其在三个正交平面（通常是地面平面、前视平面和侧视平面）上的投影来有效地表示。每个平面都捕获了场景在特定方向上的“轮廓”信息。通过将这三个2D平面的特征进行融合，可以重建出比单一BEV平面更丰富的3D结构信息。TPV表示的计算复杂度远低于全3D体素，因为它只需要处理三个2D平面。**TPVFormer**是该领域的开创性工作，它证明了仅使用相机输入，TPV表示就能达到与LiDAR方法相媲美的性能 。

##### 1.2.3.1 平面组合 (Plane Combination)

TPV表示中的三个平面通常是**正交平面（Orthogonal Planes）** ，以覆盖3D空间的主要维度。最常见的组合是鸟瞰图（BEV）、前视图（Front View）和侧视图（Side View）。这种组合能够全面地捕捉场景的水平和垂直结构信息。另一种选择是使用**柱面平面（Cylindrical Planes）** ，例如在柱坐标系下定义的三个平面。这种方法在处理以车辆为中心的场景时可能更具优势，因为它可以更自然地处理径向和角度信息。例如，**PointOcc**方法就采用了柱坐标系下的三视图表示 。

##### 1.2.3.2 融合方法 (Fusion Method)

将来自三个平面的特征有效地融合是TPV表示的关键。最简单的融合方法是**求和（Summation）** ，即直接将三个平面的特征图在对应位置相加。这种方法计算简单，但可能无法充分利用不同平面特征之间的复杂关系。另一种方法是**拼接（Concatenation）** ，即将三个平面的特征图在通道维度上进行拼接，然后通过一个卷积层或MLP层进行融合。这种方法可以保留更多的信息，但参数量也相应增加。更先进的方法是使用**注意力机制（Attention）** ，例如交叉注意力，来动态地计算不同平面特征之间的权重，从而实现更智能、更自适应的融合。**TPVFormer**就采用了交叉视图混合注意力（cross-view hybrid attention）来促进TPV平面之间的信息交互 。

### 1.3 视图转换 (View Transformation)：2D到3D的桥梁

视图转换是视觉中心Occupancy感知方法中的核心环节，它负责将2D图像特征提升到3D空间，或者将3D信息投影到2D平面。这个转换过程的质量直接决定了最终3D Occupancy预测的准确性。根据转换机制的不同，视图转换方法主要可分为三类：基于投影（Projection-Based）、基于反投影（Back-Projection-Based）和基于交叉注意力（Cross-Attention-Based） 。基于投影的方法通常将3D空间中的点投影到2D图像平面上，以获取对应的图像特征。基于反投影的方法则相反，它将2D图像特征根据某种深度假设反投影回3D空间。基于交叉注意力的方法则利用注意力机制来建立2D图像特征和3D空间表示之间的动态关联。

#### 1.3.1 基于投影 (Projection-Based)

基于投影的视图转换方法是一种相对直接的方式。它首先在3D空间中定义一个查询点（例如，一个体素的中心），然后通过已知的相机内外参，将这个3D点投影到2D图像平面上。接着，在投影位置的邻域内进行特征采样，以获得该3D点的图像特征。这种方法的优点是实现简单，计算效率较高。然而，它也存在一些问题。首先，多个3D点可能会投影到同一个2D像素上（Many-to-One映射），导致信息丢失。其次，2D图像上的特征采样（如双线性插值）可能会引入误差。

##### 1.3.1.1 映射类型 (Mapping Type)

在基于投影的方法中，映射类型决定了3D空间点和2D图像像素之间的对应关系。**一对一（One-to-One）** 映射是指每个3D点都唯一地对应一个2D像素，这种情况通常发生在3D空间分辨率较低或相机视角非常特殊的情况下。更常见的是**多对一（Many-to-One）** 映射，即多个3D点（例如，在同一视线上的不同深度的点）都投影到同一个2D像素上。在这种情况下，需要设计合理的策略来处理这种冲突，例如只取最近点的特征，或者对所有投影到该像素的3D点的特征进行聚合。

##### 1.3.1.2 采样方法 (Sampling)

当3D点被投影到2D图像平面上时，其投影位置通常不会恰好落在整数像素坐标上，因此需要进行特征采样。最常用的采样方法是**双线性插值（Bilinear Interpolation）** ，它通过对投影位置周围的四个整数像素点的特征进行加权平均，来得到该位置的平滑特征。这种方法计算简单，且能生成连续的梯度，有利于网络的反向传播。另一种简单的方法是**最近邻插值（Nearest Neighbor）** ，即直接取离投影位置最近的整数像素点的特征。这种方法计算速度更快，但生成的特征图可能不够平滑。

#### 1.3.2 基于反投影 (Back-Projection-Based)

基于反投影的视图转换方法是目前视觉中心Occupancy感知领域的主流范式。它首先在2D图像上提取特征，然后根据某种深度假设，将这些2D特征“提升”或“反投影”到3D空间中。这种方法的核心在于如何处理深度信息。与基于投影的方法相比，反投影方法能够更密集地将图像信息填充到3D空间中，并且能更好地处理深度不确定性。**LSS (Lift-Splat-Shoot)** 是一个非常著名的基于反投影的视图转换框架，它首先为每个图像像素预测一个深度分布，然后将该像素的特征沿着这条射线上的多个深度进行“提升”，最后将所有射线上的特征“溅射”（splat）到BEV平面上。

##### 1.3.2.1 深度处理 (Depth Handling)

深度信息的处理是基于反投影方法的核心。**确定性深度（Deterministic Depth）** 方法为每个像素预测一个单一的、确定的深度值。这种方法简单，但无法表达深度的不确定性。**深度分布（Depth Distribution）** 方法则为每个像素预测一个深度概率分布，表示该像素可能属于不同深度的概率。这种方法能够更好地建模深度的不确定性，是LSS等先进方法的核心。**学习深度（Learned Depth）** 方法则通过一个子网络来端到端地学习从图像特征到深度的映射，这个子网络可以与主网络联合优化。

##### 1.3.2.2 参考方法 (Reference Method)

**Lift-Splat-Shoot (LSS)** 是一种经典的基于反投影的视图转换方法。它首先将二维图像特征“提升”（Lift）到一个视锥体（Frustum）中，然后根据深度分布将特征“溅射”（Splat）到BEV平面上，最后通过“射击”（Shoot）操作来聚合特征。**MonoScene**  就采用了类似的反投影思想，将2D图像特征投影到3D空间中。

#### 1.3.3 基于交叉注意力 (Cross-Attention-Based)

基于交叉注意力的方法利用Transformer架构中的交叉注意力机制来实现视图转换。它将三维空间中的查询（Query）与二维图像特征（Key和Value）进行交互，从而将图像信息有效地聚合到三维表示中。这种方法能够建立2D和3D特征之间更灵活、更动态的关联，并且不依赖于显式的深度估计或几何投影，因此具有更强的表示能力。

##### 1.3.3.1 注意力类型 (Attention Type)

常用的注意力类型包括**标准交叉注意力（Vanilla Cross-Attention）** 、**可变形注意力（Deformable Attention）** 和**稀疏注意力（Sparse Attention）** 。标准交叉注意力计算所有查询与所有键值对之间的注意力权重，计算复杂度较高。可变形注意力则只关注一小部分关键的采样点，从而降低了计算复杂度。稀疏注意力则通过引入稀疏性来进一步减少计算量。

##### 1.3.3.2 查询与键值源 (Query & Key-Value Source)

在交叉注意力机制中，**查询（Query）** 通常来自于三维空间中的体素特征或学习得到的查询向量。**键（Key）和值（Value）** 则来自于二维图像特征。通过计算查询与键之间的相似度，可以得到注意力权重，然后利用该权重对值进行加权求和，从而得到更新后的三维特征。**TPVFormer**  和 **VoxFormer**  都采用了基于交叉注意力的视图转换方法。

### 1.4 输出头 (Output Head)：最终的预测

输出头是3D Occupancy感知算法的最后一环，它负责将网络提取的特征转换为最终的预测结果。输出头的设计取决于具体的任务需求，例如，是进行二分类的占用预测，还是进行多分类的语义占用预测。

#### 1.4.1 预测任务 (Occupancy Prediction)

占用预测任务可以分为三种类型：**二分类（Binary Classification）** 、**语义分类（Semantic Classification）** 和**开放词汇表（Open-Vocabulary）** 。二分类任务只预测每个体素是否被占用，是最基础的占用预测形式。语义分类任务则在二分类的基础上，进一步预测被占用体素的语义类别（如汽车、行人、建筑物等）。开放词汇表任务则旨在识别任意类别的物体，而不仅仅是预定义的类别，这对于处理长尾问题和未知物体具有重要意义。

#### 1.4.2 几何输出 (Geometry Output)

几何输出定义了预测结果的几何表示形式。最常见的是**体素网格（Voxel Grid）** ，它将预测结果表示为一个三维的体素阵列。近年来，随着神经辐射场（NeRF）和3D高斯溅射（3D Gaussian Splatting）技术的发展，也出现了使用**高斯表示（Gaussian Representation）** 和**隐式函数（Implicit Function）** 来输出几何信息的方法。这些新兴的几何表示方式能够更精细、更紧凑地表示三维场景。

#### 1.4.3 附加输出 (Additional Outputs)

除了基本的占用和语义信息外，一些先进的Occupancy感知算法还会输出附加信息，以增强对场景的理解。例如，**流预测（Flow Prediction）** 旨在估计每个体素或物体的运动速度和方向，这对于动态场景的理解和预测至关重要。**不确定性估计（Uncertainty Estimation）** 则旨在量化模型预测的置信度，这对于安全关键的自动驾驶应用具有重要意义，可以帮助系统识别出模型可能出错的情况，并采取相应的安全措施。

## 2. 网络架构设计：模型的骨架

### 2.1 架构范式 (Network Architecture)

网络架构是3D Occupancy感知模型的骨架，其设计直接决定了模型的特征提取能力、信息处理效率和最终的性能上限。随着深度学习技术的发展，Occupancy感知领域的网络架构也经历了从经典的卷积神经网络（CNN）到强大的Transformer，再到两者结合的混合架构，以及近年来兴起的新兴范式如神经辐射场（NeRF）和3D高斯（Gaussian）的演进。

#### 2.1.1 基于CNN (CNN-Based)

基于CNN的架构是3D Occupancy感知的早期主流方法。这类架构通过堆叠卷积层、池化层和非线性激活函数来构建层次化的特征表示。在处理3D数据时，通常会使用3D卷积核在体素化的空间中进行滑动，以提取局部空间特征。CNN架构的优势在于其强大的局部特征提取能力和对平移不变性的天然支持，这使得它在处理具有规则网格结构的数据（如体素）时非常有效。然而，CNN的感受野有限，难以捕捉长距离的依赖关系，这在理解复杂场景的全局上下文时可能成为瓶颈。此外，3D CNN的计算和内存开销巨大，限制了其在高分辨率场景中的应用。

#### 2.1.2 基于Transformer (Transformer-Based)

近年来，基于Transformer的架构在3D Occupancy感知领域取得了巨大成功，尤其是在视觉中心的方法中。Transformer架构的核心是自注意力（Self-Attention）机制，它允许模型在处理序列中的每个元素时，动态地计算其与序列中所有其他元素的关联权重。这种机制使得模型能够捕捉全局依赖关系，从而更好地理解场景的整体结构和上下文。在Occupancy感知中，Transformer被广泛应用于视图转换（如**TPVFormer**）、多模态融合和时序建模等模块。其优势在于强大的全局建模能力和灵活性，但其计算复杂度通常与输入序列长度的平方成正比，对计算资源要求较高。

#### 2.1.3 混合架构 (Hybrid CNN-Transformer)

为了结合CNN的局部感知能力和Transformer的全局建模能力，研究者们提出了混合CNN-Transformer架构。这类架构通常在模型的浅层使用CNN来提取局部特征，然后在深层使用Transformer来捕捉全局上下文。例如，一个典型的混合架构可能使用一个CNN backbone（如ResNet）来提取2D图像特征，然后通过一个基于Transformer的解码器将这些特征提升到3D空间并进行融合。这种设计既能利用CNN的高效性，又能发挥Transformer的强大表示能力，在性能和效率之间取得了良好的平衡。**MonoScene**就是一个典型的混合架构，它使用CNN处理2D图像，然后通过一个3D Transformer来生成最终的Occupancy预测 。

#### 2.1.4 新兴架构 (NeRF-Based & Gaussian-Based)

随着神经渲染技术的发展，一些新兴架构开始被应用于3D Occupancy感知。**神经辐射场（NeRF）** 通过使用一个多层感知机（MLP）来隐式地表示3D场景，可以从一组2D图像中合成具有任意视角和深度的3D场景。一些研究将NeRF的思想引入Occupancy预测，通过学习一个连续的3D场景表示，从而实现更高精度的几何重建。**3D高斯溅射（3D Gaussian Splatting）** 是另一种新兴表示，它使用一组可学习的3D高斯椭球体来表示场景，具有渲染速度快、表示紧凑的优点。**OccGS**就是一个基于3D高斯的开放词汇Occupancy重建框架，它展示了强大的零样本泛化能力 。

### 2.2 特征提取器 (Feature Extractor)

特征提取器是网络架构的核心组件，负责从原始输入数据中提取有意义的特征表示。其设计主要包括骨干网络的选择和预训练策略的制定。

#### 2.2.1 骨干网络 (Backbone Type)

骨干网络是特征提取器的主体，其选择取决于输入模态和任务需求。
*   **对于视觉输入**，常用的骨干网络包括经典的CNN架构如**ResNet**、**VGG**，以及近年来流行的Vision Transformer（**ViT**）及其变体如**Swin Transformer**。ResNet通过残差连接解决了深度网络的梯度消失问题，是视觉任务中的经典选择。ViT则将图像分割成块，并将其作为序列输入到Transformer中，展现了强大的全局建模能力。
*   **对于LiDAR输入**，由于点云是无序且稀疏的，需要专门的骨干网络。**PointNet**及其改进版**PointNet++**是处理原始点云的经典方法，它们通过共享的多层感知机（MLP）和最大池化操作来提取点云的置换不变性特征。**PointPillars**和**VoxelNet**则将点云转换为规则的柱状体或体素表示，然后应用2D或3D CNN进行处理，以提高计算效率。

#### 2.2.2 预训练策略 (Pretraining)

预训练是提升模型性能和加速收敛的有效手段。通过在大型数据集上进行预训练，模型可以学习到通用的特征表示，然后在下游任务上进行微调。
*   **ImageNet预训练**：对于视觉骨干网络，最常见的预训练策略是在大规模的ImageNet数据集上进行监督学习。这可以使模型学习到丰富的图像特征，如边缘、纹理和颜色等，为后续的3D感知任务提供良好的初始化。
*   **自监督预训练**：为了利用大量无标注的数据，自监督预训练方法被提出。这类方法通过设计巧妙的预训练任务（如图像旋转预测、对比学习等），让模型从未标注的数据中学习到有用的特征表示。例如，**MAE（Masked Autoencoder）** 通过随机掩码图像的一部分并要求模型重建，来学习鲁棒的视觉特征。
*   **无预训练**：在某些情况下，模型也可以从头开始训练（None），尤其是在输入数据与ImageNet等自然图像数据集差异较大时。

### 2.3 编码器-解码器 (Encoder-Decoder)

编码器-解码器结构是处理特征表示并进行最终预测的标准范式。编码器负责将输入特征压缩成一个紧凑的、高维的表示（瓶颈层），而解码器则负责将这个表示逐步解码，恢复到原始的空间分辨率，并生成最终的预测结果。

#### 2.3.1 维度处理 (Dimensionality)

根据任务需求，编码器-解码器可以处理不同维度的特征。
*   **2D Only**：一些方法可能只在2D平面上进行处理，例如在处理BEV特征时。
*   **3D Only**：对于基于体素的方法，编码器-解码器通常完全在3D空间中进行操作。
*   **2D+3D Dual Branch**：为了充分利用不同视图表示的优势，一些方法采用双分支结构，一个分支在2D空间（如图像或BEV）中处理，另一个分支在3D空间（如体素）中处理，然后通过跨维度的交互模块将两个分支的特征进行融合。

#### 2.3.2 卷积类型 (Convolution Type)

在编码器-解码器中，卷积是核心的操作算子。
*   **Standard Conv**：标准的卷积操作，适用于处理密集的特征图。
*   **Sparse Conv**：稀疏卷积，专门用于高效处理稀疏数据（如LiDAR点云体素化后的表示），只对非空体素进行计算，极大地节省了计算资源。
*   **Deformable Conv**：可变形卷积，其卷积核的采样位置是可学习的，能够自适应地调整感受野，从而更好地捕捉物体的几何形变。

#### 2.3.3 Transformer类型 (Transformer Type)

在基于Transformer的架构中，注意力机制的类型也多种多样。
*   **Standard Attention**：标准的自注意力或交叉注意力机制，计算所有位置之间的关联。
*   **Deformable Attention**：可变形注意力，与可变形卷积类似，它只关注一小部分关键的采样点，从而降低计算复杂度。
*   **Windowed Attention**：窗口注意力，将特征图划分为不重叠的窗口，只在每个窗口内部计算自注意力，从而将计算复杂度降低到线性级别。**Swin Transformer**就是基于这种思想。

## 3. 信息融合策略：多源信息的协同

在自动驾驶的复杂动态环境中，单一传感器因其固有的物理限制，无法在所有场景下提供鲁棒且全面的环境感知。例如，摄像头在光照不足或恶劣天气下性能会急剧下降，而激光雷达（LiDAR）虽然能提供精确的几何信息，但在识别远距离或纹理稀疏的物体时可能力不从心。因此，信息融合（Information Fusion）技术应运而生，它通过整合来自不同传感器、不同时间戳的多源信息，旨在构建一个比任何单一信息源都更准确、更完整、更可靠的环境模型。这一过程不仅是简单的数据叠加，而是涉及在数据、特征或决策层面进行复杂的对齐、关联与推理，以克服各传感器的局限性，实现“1+1>2”的协同效应。根据融合发生的信息处理阶段，信息融合通常被划分为三个层次：数据级融合（Data-Level Fusion）、特征级融合（Feature-Level Fusion）和决策级融合（Decision-Level Fusion）。在3D Occupancy感知的框架下，这些策略进一步演化为对空间信息（多相机、多模态）和时间信息（多帧）的精细化处理，构成了算法设计的核心挑战与创新点。

### 3.1 空间融合 (Spatial Fusion)

空间融合旨在整合来自不同空间视角或不同物理原理传感器的信息，以构建一个统一、无歧义的3D场景表示。这主要包括两个层面：一是将多个摄像头（如环视摄像头系统）捕捉到的2D图像信息融合成一个连贯的3D表示；二是将来自不同模态（如摄像头、LiDAR、Radar）的异构数据进行深度融合，以充分利用各自的互补优势。摄像头擅长捕捉丰富的语义和纹理信息，而LiDAR和Radar则能提供精确的几何和深度信息，且对环境光照不敏感。通过有效的空间融合，系统能够弥补单一传感器的感知盲区，提升对物体几何形状、语义类别和空间位置的认知精度，尤其是在处理遮挡、远距离探测和复杂光照条件等挑战性场景时，其优势尤为突出。

#### 3.1.1 多相机融合 (Camera Fusion)

在多相机系统中，车辆周围部署的多个摄像头共同覆盖了360度的视野范围。将这些具有不同视角的图像信息融合成一个统一的3D空间表示，是视觉中心Occupancy感知方法的关键步骤。这一过程的核心挑战在于如何处理不同相机间的视角差异和视野重叠问题。

##### 3.1.1.1 融合方法 (Method)

多相机融合的方法多种多样，从简单的特征拼接（Concatenation）到复杂的基于注意力的交互机制。早期的融合方法可能直接将不同视角的特征图在通道维度上进行拼接，但这忽略了特征之间的空间对应关系。更先进的方法，如**交叉注意力（Cross-Attention）** ，允许一个视角的特征去查询并聚合其他视角中的相关信息。例如，一个视角中的特征可以作为查询（Query），而其他视角的特征则作为键（Key）和值（Value），通过计算注意力权重，模型可以动态地决定从其他视角中“借用”多少信息来增强当前视角的特征表示。这种方法能够有效地处理非重叠视野（Non-Overlapping FOV）的情况，即当一个物体仅出现在一个相机的视野中时，可以通过与其他相机特征的交互来推断其完整信息。此外，一些方法采用“直通”（Straight-Through）策略，即在视图转换（View Transformation）之后，将所有相机在3D空间（如BEV空间）中生成的特征图进行直接融合，这种方式简化了融合过程，但可能损失部分2D图像中的细粒度信息。

##### 3.1.1.2 视野重叠 (View Overlap)

处理相机间的**视野重叠（Overlapping FOV）** 是提升融合质量的关键。在重叠区域，同一个3D空间点会被多个相机观测到，这为深度估计和几何一致性校验提供了冗余信息。有效的融合策略应该能够利用这种冗余来提升预测的鲁棒性。例如，可以通过三角测量原理，利用重叠区域的像素对应关系来更精确地计算深度。在基于Transformer的架构中，交叉注意力机制天然地适合处理重叠区域。模型可以学习到在重叠区域内，如何对不同相机的观测结果进行加权融合，甚至可以利用一个相机的清晰观测来补偿另一个相机中因运动模糊或遮挡而模糊的观测。对于**非重叠视野（Non-Overlapping FOV）** ，融合的挑战更大，因为缺乏直接的像素对应关系。此时，模型需要依赖于对场景的整体理解和上下文推理，例如，通过识别物体的部分特征并结合其运动学模型，来推断其在未观测区域的几何和语义信息。

#### 3.1.2 多模态融合 (Multi-Modal Fusion)

多模态融合是提升Occupancy感知系统鲁棒性和准确性的终极手段。通过结合摄像头、LiDAR、Radar乃至文本等不同来源的信息，系统可以获得对环境的全面理解。例如，LiDAR提供的高精度深度信息可以极大地改善视觉方法在深度估计上的不确定性，而摄像头提供的丰富语义信息则可以弥补LiDAR点云在识别物体类别上的不足。这种融合策略的核心在于如何有效地对齐和整合这些在数据格式、稀疏性和信息密度上差异巨大的模态。

##### 3.1.2.1 融合阶段 (Stage)

根据融合发生的时间点，多模态融合可分为**早期融合（Early Fusion）** 、**中期融合（Mid-Fusion）** 和**后期融合（Late Fusion）** 。

*   **早期融合（数据级融合）** ：在特征提取之前，直接将不同模态的原始数据进行融合。例如，将LiDAR点云投影到图像平面，生成深度图或RGB-D图像，然后与原始RGB图像一起输入到网络中。这种方法的优点是能够最大限度地保留各模态的原始信息，但缺点是数据维度高，计算量大，且对传感器间的时空同步要求极高。

*   **中期融合（特征级融合）** ：这是目前最主流和有效的融合方式。它首先在各个独立的网络分支中对不同模态的数据进行特征提取，然后在网络的中间层将这些特征图进行融合。例如，一个分支处理图像特征，另一个分支处理体素化的LiDAR点云特征，随后在某个共享的表示空间（如BEV空间）中，通过拼接、加权求和或交叉注意力等方式将两种特征融合。这种方法在保留模态特有信息和实现高效融合之间取得了良好的平衡。例如，**FusionOcc**模型就在2D和3D空间分别进行特征融合，通过交叉模态模块融合图像和LiDAR深度图，再在3D空间中对齐和合并体素化点云特征与视图转换后的图像特征。

*   **后期融合（决策级融合）** ：每个模态独立地完成其感知任务（如分别生成一个Occupancy预测结果），然后在决策层面对这些结果进行融合。例如，可以对不同模态的预测结果进行投票或加权平均。这种方法的优点是模块化程度高，易于实现和调试，但缺点是模态间的交互信息有限，无法充分利用跨模态的互补性。

##### 3.1.2.2 融合技术 (Technique)

实现多模态融合的具体技术手段多种多样，从简单的数学运算到复杂的动态交互机制。

*   **拼接与求和（Concatenation & Summation）** ：这是最直接的融合方式。将不同模态的特征图在通道维度上拼接，或者进行逐元素相加。拼接操作保留了所有信息，但会增加后续层的计算负担。求和操作则是一种信息压缩，但可能无法充分表达模态间的复杂关系。

*   **交叉注意力（Cross-Attention）** ：这是目前最先进的融合技术之一，尤其是在Transformer架构中。它允许一个模态的特征（作为Query）去主动地查询和聚合另一个模态（作为Key和Value）中的相关信息。例如，在**MR-Occ**模型中，利用可变形注意力机制（Deformable Attention）来有效地融合相机和LiDAR数据，使得模型能够聚焦于两种模态中最具信息量的区域。**TransFuser**模型则利用Transformer的注意力机制来整合图像和LiDAR表示，以捕捉3D场景的全局上下文，从而在复杂的城市驾驶场景中显著减少碰撞。

*   **动态融合（Dynamic Fusion）** ：与静态的拼接或求和不同，动态融合机制会根据输入数据的内容自适应地调整融合权重。例如，通过学习一组可学习的权重，或者利用Squeeze-and-Excitation（SE）模块来重新校准不同模态特征的通道重要性。在**MS-Occ**框架中，自适应融合（AF）模块能够动态地平衡不同模态的体素特征，而高分类置信度体素融合（HCCVF）模块则利用自注意力来解决语义不一致的问题。这种自适应能力使得模型能够根据场景的具体情况（如光照、天气、物体距离）来决定更信赖哪个传感器的信息。

##### 3.1.2.3 自适应机制 (Adaptive Mechanism)

为了让融合过程更加智能和鲁棒，研究者们引入了多种自适应机制。这些机制的核心思想是让模型能够根据输入数据的动态变化，自动调整融合策略。

*   **可学习权重（Learnable Weights）** ：模型可以学习一组权重，用于在融合时对不同模态的特征进行加权。这些权重可以是全局的，也可以是针对每个空间位置或每个通道的。例如，**M3Net**模型中的模态自适应特征集成（MAFI）模块，允许单模态特征为其各自擅长的任务预测通道级的注意力权重，从而实现更精细的融合控制。

*   **Squeeze-and-Excitation (SE) 模块**：SE模块是一种轻量级的注意力机制，它通过“挤压”（Squeeze）操作获取全局信息，再通过“激励”（Excitation）操作学习各个通道的重要性，最后通过重新加权来增强有用的特征，抑制无用的特征。在多模态融合中，SE模块可以被用来校准不同模态特征的重要性。

*   **KNN引导（KNN-Guided）** ：在一些基于点云的融合方法中，可以利用K近邻（K-Nearest Neighbors）算法来建立不同模态特征之间的对应关系。例如，对于一个LiDAR点，可以在图像特征图上找到其最近的K个像素点，然后根据这些邻居的特征来增强该点的表示。这种基于几何邻近性的引导方式，能够实现更精确的特征对齐和融合。

### 3.2 时间融合 (Temporal Fusion)

时间融合旨在利用连续帧之间的信息冗余和动态变化，来提升Occupancy感知的稳定性和对动态环境的理解能力。现实世界是动态的，车辆、行人等物体都在不断运动。通过融合历史帧的信息，模型不仅可以获得更密集的观测（例如，通过多帧累积来“看到”被遮挡的区域），还可以推断物体的运动状态（如速度、方向），这对于预测未来场景和规划安全路径至关重要。

#### 3.2.1 对齐方法 (Alignment Method)

在进行时间融合之前，首要任务是将不同时间戳的观测数据对齐到同一个坐标系下。由于车辆在运动，不同时刻的传感器数据处于不同的“自我坐标系”中。

*   **基于位姿的变换（Pose-Based Warping）** ：这是最常用的对齐方法。通过车辆的IMU（惯性测量单元）和轮速计等传感器，或者通过SLAM（即时定位与地图构建）算法，可以估计出车辆在不同时刻之间的相对位姿变换（即旋转和平移）。利用这个变换矩阵，可以将历史帧的3D特征（如体素或点云）“扭曲”（Warp）到当前帧的坐标系中。这种方法简单直接，但对位姿估计的精度要求很高，位姿漂移会导致对齐误差。

*   **基于光流的变换（Flow-Based Warping）** ：在视觉领域，光流（Optical Flow）描述了图像中像素点的运动。通过估计连续帧之间的光流场，可以将历史帧的图像特征图扭曲到当前帧。这种方法在2D层面有效，但将其扩展到3D Occupancy的融合则更具挑战性。

*   **基于注意力的对齐（Attention-Based Alignment）** ：一些先进的方法利用注意力机制来隐式地学习时间对齐。例如，在**UVTR**模型中，通过引入基于查询的记忆机制，利用时序BEV token来关注前一帧的特征，从而实现信息的保留和融合。这种方法不依赖于显式的位姿估计，而是通过数据驱动的方式学习如何对齐和融合时序信息，对位姿误差具有更强的鲁棒性。

#### 3.2.2 融合机制 (Fusion Mechanism)

将多帧对齐后的特征进行融合，可以采用多种机制。

*   **3D卷积（3D Convolution）** ：将时间维度视为一个额外的空间维度，使用3D卷积核来同时处理空间和时间信息。这种方法可以捕捉到局部时空内的模式，但计算量较大，且感受野有限。

*   **交叉注意力（Cross-Attention）** ：与时间对齐类似，交叉注意力机制可以用于时间融合。当前帧的特征可以作为Query，去查询和聚合历史帧（作为Key和Value）中的相关信息。例如，**Sparse4D**模型引入了稀疏4D注意力结构，使得动态查询能够从体素化表示中选择时空特征，从而实现对空间和时间的自适应选择。

*   **自适应混合（Adaptive Mixing）** ：类似于空间融合中的动态融合，时间融合也可以采用自适应机制。模型可以学习如何根据场景动态（如物体运动速度）来调整历史信息的权重。例如，在快速变化的场景中，可能更信赖当前帧的信息；而在静态场景中，则可以更多地依赖历史累积信息。

*   **拼接与卷积（Concatenation + Conv）** ：一种简单有效的方法是将对齐后的多帧特征在通道维度上拼接，然后通过一个或多个2D/3D卷积层来融合这些信息。这种方法实现简单，且卷积操作能够学习到帧间的复杂关系。

#### 3.2.3 历史帧处理 (Historical Frames)

处理历史帧的策略决定了模型能够利用多长时间范围的信息。

*   **单前一帧（Single Previous Frame）** ：只融合紧邻的前一帧信息。这种方法计算开销小，易于实现，但无法利用更长远的时序上下文。

*   **多帧（Multiple Frames）** ：融合固定数量的历史帧（例如，前N帧）。这可以通过维护一个固定大小的时序缓冲区来实现。这种方法能够提供更丰富的时序信息，但计算量和内存消耗也随之增加。

*   **滑动窗口（Sliding Window）** ：这是一种处理多帧的常用方式，即在一个固定长度的时间窗口内进行融合，窗口随着时间向前滑动。这可以看作是一种在线的处理方式，适用于实时应用。

*   **循环网络（Recurrent Networks）** ：使用RNN（循环神经网络）或其变体（如LSTM、GRU）来处理时序信息。RNN通过其内部的隐藏状态来记忆历史信息，理论上可以处理任意长度的序列。然而，传统的RNN存在梯度消失/爆炸问题，难以捕捉长距离依赖关系。

*   **世界模型（World Model）** ：更前沿的方法试图构建一个内部的“世界模型”，该模型不仅融合历史信息，还能基于当前观测和动作来预测未来的场景状态。这种模型能够进行更深层次的时序推理，是实现高级别自动驾驶的关键。

## 4. 训练与优化：模型的学习与成长

### 4.1 训练策略 (Training Strategy)

训练策略定义了模型如何从数据中学习，是模型性能的关键决定因素。根据监督信号的强弱和来源，训练策略可以分为强监督、弱监督和自监督等多种类型。

#### 4.1.1 强监督 (Strong Supervision)

强监督学习依赖于大量精确、稠密的3D Occupancy标签进行训练。这是目前最主流的训练方式，能够直接引导模型学习从输入到输出的精确映射。

##### 4.1.1.1 标签类型 (Label Type)

强监督下的标签通常是**稠密的3D Occupancy网格**或**语义体素（Semantic Voxels）** 。每个体素都被标注了其是否被占用以及所属的语义类别。这种标签提供了最直接、最丰富的监督信息，但获取成本极高。

##### 4.1.1.2 标注来源 (Annotation Source)

这些稠密标签的来源主要有三种：
*   **手动标注（Manual）** ：由人工在3D空间中逐个体素地进行标注，这是最精确但也是最耗时耗力的方法。
*   **半自动标注（Semi-Automated）** ：结合自动化算法和少量人工修正来生成标签，可以在保证一定精度的同时提高效率。
*   **LiDAR累积（LiDAR Accumulation）** ：通过融合多帧LiDAR点云数据，生成一个相对稠密的点云，然后将其体素化作为Occupancy标签。这是目前生成大规模Occupancy数据集（如SemanticKITTI、nuScenes-Occupancy）的主要方法。

#### 4.1.2 弱监督 (Weak Supervision)

弱监督学习旨在利用更容易获取的、不完整的或间接的监督信号来训练模型，以降低对昂贵稠密标签的依赖。

##### 4.1.2.1 信号源 (Signal Source)

弱监督的信号源多种多样，包括：
*   **语义点云（Semantic Point Clouds）** ：只标注了语义类别的稀疏LiDAR点云。
*   **深度图（Depth Maps）** ：由LiDAR或立体视觉生成的深度信息。
*   **2D语义分割（2D Semantic Segmentation）** ：在图像平面上进行的像素级语义标注。

##### 4.1.2.2 渲染方法 (Rendering Method)

为了利用这些弱监督信号，通常需要借助可微分的渲染技术，将3D Occupancy预测结果投影到2D平面，然后与2D标签进行比较。
*   **体积渲染（Volume Rendering）** ：沿着相机射线对3D体素进行积分，生成2D图像。
*   **可微分渲染（Differentiable Rendering）** ：一种更通用的渲染框架，允许将3D场景表示（如网格、点云）渲染成2D图像，并且整个过程是可微分的，从而可以进行端到端的训练。

#### 4.1.3 自监督 (Self-Supervision)

自监督学习是一种特殊的无监督学习，它通过设计预训练任务（Pretext Task）从未标注的数据中自动生成监督信号。这种方法在Occupancy感知领域也显示出巨大潜力。

##### 4.1.3.1 一致性类型 (Consistency Type)

自监督的核心思想是“一致性”。模型被训练以在不同视图或不同条件下产生一致的预测。
*   **光度一致性（Photometric Consistency）** ：假设同一场景在不同视角或不同时间点的图像应该具有相似的外观。
*   **几何一致性（Geometric Consistency）** ：假设3D场景的几何结构在不同视角下应该保持一致。
*   **跨视图一致性（Cross-View Consistency）** ：将多相机系统作为一个自监督的信号，要求模型从不同视角的图像中预测出一致的3D场景。

##### 4.1.3.2 辅助任务 (Auxiliary Task)

为了实现自监督，通常会设计一些辅助任务：
*   **深度估计（Depth Estimation）** ：从单张或多张图像中估计深度。
*   **位姿估计（Pose Estimation）** ：估计相机或车辆的运动。
*   **新视角合成（Novel View Synthesis）** ：从一组已知视角的图像中，合成任意新视角的图像。

### 4.2 损失函数 (Loss Functions)

损失函数是模型训练优化的目标，它量化了模型预测与真实标签之间的差距。在3D Occupancy感知任务中，通常会组合多种损失函数来同时优化几何、语义和其他方面的性能。

#### 4.2.1 几何损失 (Geometric Losses)

几何损失主要用于优化模型对空间占用状态的预测。
*   **BCE (Binary Cross-Entropy)** ：二分类交叉熵损失，常用于二分类的Occupancy预测任务，衡量预测占用概率与真实标签（0或1）之间的差距。
*   **Scale-Invariant Log Loss**：尺度不变对数损失，对深度预测中的尺度误差不敏感，常用于深度估计任务。
*   **Soft-IoU Loss**：软IoU损失，是IoU指标的可微分版本，可以直接优化IoU，通常比BCE损失能取得更好的几何重建效果。

#### 4.2.2 语义损失 (Semantic Losses)

语义损失用于优化模型对语义类别的预测。
*   **CE (Cross-Entropy)** ：交叉熵损失，是多分类任务中最常用的损失函数。
*   **Lovasz-Softmax**：Lovasz-Softmax损失，是mIoU指标的可微分近似，通过直接优化mIoU来提升语义分割的性能。
*   **Focal Loss**：焦点损失，通过为难分样本分配更高的权重，来解决类别不平衡问题，尤其适用于存在大量“背景”或“空闲”体素的Occupancy任务。
*   **Frustum Proportion Loss**：视锥体比例损失，用于约束模型预测的3D语义分布与2D图像中的语义分布保持一致。
*   **Position Awareness Loss**：位置感知损失，用于增强模型对物体空间位置的感知能力。

#### 4.2.3 组合与一致性损失 (Combined & Consistency Losses)

为了进一步提升模型性能，通常会引入组合损失和一致性损失。
*   **Scene-Class Affinity Loss**：场景-类别亲和损失，用于学习场景上下文与语义类别之间的关系。
*   **Mask Classification Loss**：掩码分类损失，借鉴了DETR等模型的思想，将Occupancy预测视为一个集合预测问题。
*   **Spatial Consistency**：空间一致性损失，用于约束相邻体素之间的预测具有一致性。
*   **Photometric Consistency**：光度一致性损失，用于自监督训练。
*   **Modality Alignment Loss**：模态对齐损失，用于约束不同模态的特征在共享空间中具有相似的分布。
*   **KL Divergence / Feature Distillation**：知识蒸馏损失，用于将一个大型“教师”模型的知识迁移到一个较小的“学生”模型中。

## 5. 性能与评估：模型的度量衡

在自动驾驶领域，3D Occupancy感知算法的性能评估是一个多维度、多层次的复杂过程。它不仅要求模型能够精确地重建三维场景的几何结构，还需要理解其中的语义信息，并在动态环境中保持时序一致性。为了全面、客观地衡量这些能力，研究社区建立了一套完整的评估体系，涵盖了从基础的准确性指标到模型的效率、鲁棒性和泛化能力等多个方面。这一体系不仅为算法间的公平比较提供了基准，也为模型的迭代优化指明了方向。本章节将深入探讨这些评估维度，解析其核心指标、评估方法以及在实际应用中的考量。

### 5.1 评估指标 (Evaluation Metrics)

评估指标是量化模型性能的标尺，其设计直接反映了任务的核心目标。在3D Occupancy感知任务中，评估指标主要分为几何、语义、时序和效率四大类，分别对应空间占用、类别识别、动态感知和计算资源消耗等不同层面的性能要求。

#### 5.1.1 空间层级 (Spatial Level)

评估指标的选择与评估的空间层级紧密相关。不同的空间层级关注不同的粒度和场景理解深度，从而衍生出不同的评估方法。

*   **体素级别 (Voxel-Level)** ：这是最基础也是最常见的评估层级。它将三维空间划分为规则的体素网格，并在每个体素上进行评估。这种方法的优点是直观、易于实现，并且能够直接反映模型对三维空间占用的预测能力。然而，体素级别的评估也存在明显的局限性。首先，由于激光雷达（LiDAR）扫描的固有特性，其点云分布不均且存在遮挡，导致通过累积点云生成的真值标签（Ground Truth）并不完美。例如，未被激光束扫描到的区域会被错误地标注为“空闲”，这会给评估带来噪声。其次，对于场景中的一些薄壁结构或细长物体，体素级别的指标过于严苛。一个体素的预测偏差就可能导致整个物体的IoU（Intersection over Union）降为零，无法真实反映模型的感知能力 。

*   **光线级别 (Ray-Level)** ：为了克服体素级别评估的不足，研究者们提出了光线级别的评估方法。该方法模仿了激光雷达的射线投射过程，其核心思想是评估从传感器原点发出的每一条射线，直到它第一次击中某个物体表面。在光线级别评估中，一个预测被认为是真正例（True Positive），需要满足两个条件：一是预测的语义类别与真值类别一致；二是预测的深度与真值深度的L1误差小于一个预设的阈值。这种方法能够更鲁棒地处理薄物体和遮挡问题，因为它关注的是射线与表面的交点，而不是整个体素网格的占用状态。例如，**SparseOcc**方法就采用了这种评估方式，并在此基础上提出了结合运动信息的OccScore指标 。

*   **实例级别 (Instance-Level)** ：实例级别的评估则更进一步，它不仅关注单个体素或射线的预测，而是将整个物体作为一个实例进行评估。这种方法通常用于评估模型对动态物体的感知和跟踪能力。例如，在评估Occupancy Flow（占用流）时，实例级别的指标可以衡量模型对每个动态物体（如车辆、行人）的运动状态（如速度、方向）的预测准确性。虽然实例级别的评估能够提供更宏观、更具应用价值的性能洞察，但其标注成本极高，且评估算法也更为复杂，因此在目前的基准测试中尚未大规模普及。

#### 5.1.2 几何与语义指标 (Geometric & Semantic Metrics)

几何和语义是3D Occupancy感知的两大核心任务，其评估指标也相应地分为两类。

*   **几何指标 (Geometric Metrics)** ：几何指标主要衡量模型对三维空间占用状态的预测准确性，不考虑语义类别。最经典的几何指标是**交并比 (Intersection over Union, IoU)** 。其计算公式为：
    $$
    \text{IoU} = \frac{TP}{TP + FP + FN}
    $$
    其中，TP（True Positive）是正确预测的占用体素数量，FP（False Positive）是错误预测为占用的体素数量，FN（False Negative）是错误预测为空闲的体素数量。IoU的值域在0到1之间，越高表示模型的几何重建能力越强。这个指标适用于二分类的占用预测任务，即只判断每个体素是“占用”还是“空闲” 。

*   **语义指标 (Semantic Metrics)** ：当模型需要同时预测占用状态和语义类别时，就需要使用语义指标。**平均交并比 (Mean Intersection over Union, mIoU)** 是最常用的语义评估指标。其计算方法是，首先对每个语义类别（通常不包括“空闲”或“未知”类别）单独计算IoU，然后对所有类别的IoU取平均值。公式如下：
    $$
    \text{mIoU} = \frac{1}{N_C} \sum_{i=1}^{N_C} \frac{TP_i}{TP_i + FP_i + FN_i}
    $$
    其中，$N_C$是语义类别的总数，$TP_i, FP_i, FN_i$分别是第$i$个类别的真正例、假正例和假反例数量。mIoU能够全面地反映模型在不同类别上的分割性能，是衡量语义-几何联合感知能力的主要标准 。

#### 5.1.3 时间与效率指标 (Temporal & Efficiency Metrics)

对于动态场景的理解，时序一致性和计算效率是至关重要的评估维度。

*   **时间指标 (Temporal Metrics)** ：时间指标主要用于评估模型对场景动态变化的感知能力，特别是对物体运动的预测。**平均绝对速度误差 (Mean Absolute Velocity Error, mAVE)** 是一个典型的时间指标，它衡量模型预测的物体速度与真值速度之间的平均绝对误差。这个指标通常与光线级别的mIoU结合使用，以全面评估动态感知性能。例如，OccScore指标就是将光线级别的mIoU和mAVE进行加权组合：
    $$
    \text{OccScore} = \text{mIoU} \times 0.9 + \max(1 - \text{mAVE}, 0.0) \times 0.1
    $$
    这个综合指标既考虑了语义几何的准确性，也考虑了动态感知的精度，为评估动态场景下的Occupancy预测提供了一个更全面的视角 。

*   **效率指标 (Efficiency Metrics)** ：效率指标衡量模型在实际部署中的可行性，主要包括**帧率 (Frames Per Second, FPS)** 、**内存占用 (Memory Usage)** 和**浮点运算次数 (Floating Point Operations, FLOPs)** 。FPS反映了模型的实时处理能力，是自动驾驶系统安全运行的关键。内存占用则关系到模型能否在车载计算单元上顺利运行。FLOPs是衡量模型计算复杂度的理论指标。在实际评估中，通常会在这三者之间进行权衡。例如，**OccLinker**方法就通过其轻量级设计，在将SurroundOcc的IoU和mIoU分别提升5.18%和1.82%的同时，相比其他时序方法，将训练内存降低了65%，推理速度提升了54%，展示了其在效率和性能之间的良好平衡 。

### 5.2 效率设计 (Efficiency Design)

随着3D Occupancy感知模型日益复杂，其在计算和内存上的开销也成为制约其落地应用的关键瓶颈。因此，效率设计成为模型架构中不可或缺的一环。研究者们从内存和计算两个维度出发，探索了多种优化策略，旨在实现性能与效率的最佳平衡。

#### 5.2.1 内存效率 (Memory Efficiency)

内存效率主要关注如何降低模型在运行过程中的内存占用，这对于资源受限的车载硬件至关重要。

*   **稀疏卷积 (Sparse Convolution)** ：这是处理稀疏数据（如LiDAR点云）时最常用的技术。由于点云在三维空间中分布非常稀疏，传统的密集卷积（Dense Convolution）会对大量的空体素进行无效计算，造成巨大的内存和计算浪费。稀疏卷积通过只计算非空体素（激活体素）及其邻域，并维护一个哈希表来记录激活体素的位置，从而避免了这种浪费。这种方法可以显著降低内存占用和计算量，是LiDAR-Centric或基于体素表示的模型（如VoxelNet）的核心优化手段。

*   **稀疏表示 (Sparse Representation)** ：除了稀疏卷积，采用稀疏的数据结构来表示中间特征也是提高效率的关键。例如，使用八叉树（Octree）或哈希表来存储体素特征，而不是使用固定的三维张量。**TopNet**就是一个典型的例子，它直接在八叉树结构上进行操作，利用自适应长度的滑动窗口注意力机制来处理不同层级的节点，从而在保持全局信息交互能力的同时，极大地降低了内存消耗 。

*   **通道到高度 (Channel-to-Height)** ：这是一种针对BEV（Bird's-Eye-View）表示的优化技巧。在将多视角图像特征转换到BEV空间时，通常会将图像特征的高度维度压缩到通道维度中。例如，将一张HxWxC的特征图，通过特定的变换，变成一个BxBx(H*C)的BEV特征图。这样做的好处是，可以在后续的BEV处理阶段使用高效的2D卷积，而不是计算量巨大的3D卷积，从而在保持高度信息的同时，显著降低计算和内存开销。

#### 5.2.2 计算效率 (Computation Efficiency)

计算效率旨在减少模型的计算量，提高推理速度，以满足自动驾驶的实时性要求。

*   **2D替代3D卷积 (2D Instead of 3D Conv)** ：这是最直接有效的优化方法之一。由于3D卷积的计算复杂度随着核大小和特征图尺寸呈立方增长，其开销远大于2D卷积。许多方法通过巧妙的设计，将3D问题转化为2D问题来处理。例如，BEV-based的方法将三维场景投影到二维鸟瞰图上，然后就可以使用成熟的2D CNN进行处理。**TPVFormer**则更进一步，它将三维空间分解为三个正交的平面（俯视、正视、侧视），在每个平面上进行2D特征提取，最后再进行融合，从而完全避免了3D卷积的使用 。

*   **可变形注意力 (Deformable Attention)** ：在基于Transformer的架构中，自注意力机制的计算复杂度与序列长度的平方成正比，这在处理高分辨率的图像或体素特征时会成为瓶颈。可变形注意力通过让每个查询（Query）只关注其周围的一小部分关键采样点，而不是整个特征图，从而将计算复杂度降低到线性级别。这种方法在**BEVFormer++** 等模型中被广泛应用，用于高效地从多视角图像中采样特征，构建BEV表示 。

*   **张量分解 (Tensor Decomposition)** ：这是一种更为底层的优化技术，通过将高维张量分解为多个低维张量的乘积来降低计算量。例如，可以将一个大的卷积核分解为两个小的卷积核的级联，或者将一个全连接层的权重矩阵分解为两个低秩矩阵的乘积。这种方法可以在几乎不损失性能的情况下，显著减少模型的参数量和计算量。

### 5.3 鲁棒性考量 (Robustness Considerations)

自动驾驶系统需要在各种复杂、多变甚至恶劣的环境中稳定运行，这对3D Occupancy感知模型的鲁棒性提出了极高的要求。鲁棒性考量旨在提升模型应对分布外（Out-of-Distribution, OOD）数据、传感器故障和恶劣天气等挑战的能力。

#### 5.3.1 架构设计 (Architectural)

通过巧妙的网络架构设计，可以从根本上提升模型的鲁棒性。

*   **多模态冗余 (Multi-Modal Redundancy)** ：这是提升鲁棒性的最有效手段之一。通过融合来自不同传感器（如摄像头、LiDAR、Radar）的信息，模型可以在某个传感器失效或性能下降时，依靠其他传感器的信息来维持感知能力。例如，在雨、雪、雾等恶劣天气下，LiDAR的性能会严重下降，此时视觉或Radar信息就可以作为有效的补充。**TEOcc**就是一个雷达-相机多模态融合的网络，旨在利用雷达的鲁棒性来增强整体感知性能 。然而，需要注意的是，一些研究发现，现有的多模态融合模型（如BEVFusion和Transfusion）在训练过程中可能对LiDAR信息产生了过强的依赖，当LiDAR完全失效时，性能会急剧下降（mAP下降89%和95%），这表明如何设计真正均衡和冗余的多模态融合架构仍是一个开放问题 。

*   **掩码重建 (Masked Reconstruction)** ：这种技术借鉴了自监督学习中的掩码语言模型（如BERT）的思想。在训练过程中，随机地掩码掉一部分输入特征（如图像的某些区域或LiDAR的某些点），然后要求模型重建这些被掩码的部分。这可以迫使模型学习更加鲁棒和完整的场景表示，而不是仅仅依赖于局部的、脆弱的线索。当遇到传感器部分遮挡或数据丢失时，这种能力就显得尤为重要。

*   **不确定性建模 (Uncertainty Modeling)** ：在模型的输出中引入不确定性估计，可以为下游的规划和决策模块提供重要的参考信息。例如，模型可以输出每个体素占用概率的置信度。对于置信度低的区域，系统可以采取更保守的驾驶策略。这种显式的不确定性建模有助于系统在感知信息不明确时做出更安全的决策。

#### 5.3.2 训练策略 (Training)

除了架构设计，训练策略也是提升鲁棒性的重要途径。

*   **损坏增强 (Corruption Augmentation)** ：这是一种直接且有效的数据增强方法。在训练数据中，人为地加入各种模拟真实世界干扰的“损坏”，如图像的模糊、噪声、过曝、欠曝，以及LiDAR点的随机丢失、位置偏移等。通过让模型在这些“困难”样本上进行学习，可以显著提升其对各种干扰的抵抗能力。**RoboBEV**和**RoboDrive**等基准测试就提供了包含多种损坏类型的数据集，用于系统性地评估和提升模型的鲁棒性 。

*   **知识蒸馏 (Knowledge Distillation from Clean Data)** ：这种方法旨在让一个在“干净”数据上训练好的、性能优异的“教师模型”来指导一个在“损坏”数据上训练的“学生模型”。通过最小化学生模型和教师模型输出之间的差异（如使用KL散度损失），可以让学生模型学会教师模型对场景的鲁棒理解能力，即使它只在有噪声的数据上进行训练。这种方法可以在不增加推理开销的情况下，有效提升模型的鲁棒性。

### 5.4 泛化能力 (Generalization Capability)

泛化能力是指模型在未见过的场景、类别或数据集上表现良好的能力。这对于自动驾驶系统应对现实世界中无穷无尽的新情况至关重要。泛化能力主要体现在两个方面：开集识别和零样本/少样本学习。

#### 5.4.1 闭集与开集 (Closed-Set & Open-Vocabulary)

*   **闭集 (Closed-Set)** ：大多数现有的Occupancy感知模型都属于闭集模型。这意味着它们只能识别和分割在训练集中出现过的、预先定义好的语义类别。例如，一个模型如果在nuScenes数据集上训练，它通常只能识别该数据集中定义的16个类别。当遇到一个训练集中没有的物体（如一个奇怪的障碍物）时，闭集模型通常只能将其归类为“背景”或“未知”，而无法提供更丰富的语义信息。这种局限性在复杂的开放道路环境中是一个严重的安全隐患。

*   **开集/开放词汇 (Open-Vocabulary)** ：为了克服闭集模型的局限性，开放词汇（或称开集）Occupancy感知应运而生。这类模型的目标是能够识别和描述在训练阶段从未见过的物体类别。实现这一目标的关键在于利用大规模预训练的视觉-语言模型（Vision-Language Models, VLMs），如**CLIP**。通过将视觉特征与文本描述（如“一个红色的消防栓”）对齐，模型可以利用语言模型的强大泛化能力来理解新类别的概念。**OccGS**就是一个典型的开放词汇Occupancy重建框架，它利用VLM提供的语义信息和LiDAR提供的几何先验，实现了对新类别的高质量重建和语义理解 。

#### 5.4.2 少样本与零样本 (Few-Shot & Zero-Shot)

*   **零样本 (Zero-Shot)** ：零样本学习是开放词汇泛化的一个极端情况，它要求模型在没有任何新类别标注样本的情况下，直接进行识别和分割。这完全依赖于模型从大规模预训练中学到的泛化知识。**OccGS**展示了强大的零样本泛化能力，它在一个数据集（如Occ3D-nuScenes）上训练后，可以直接在另一个具有不同语义类别、传感器参数和体素大小的数据集（如SemanticKITTI）上进行推理，并取得与有监督方法相媲美的性能。这证明了其基于重建和语义-几何感知高斯表示（SGAG）的框架具有出色的跨数据集泛化能力 。

*   **少样本 (Few-Shot)** ：少样本学习则介于有监督和零样本之间，它允许模型在只有极少数（如1-5个）新类别标注样本的情况下进行学习。这在实际应用中非常有价值，因为为新出现的每一种障碍物都收集大量标注数据是不现实的。通过元学习（Meta-Learning）或参数高效微调（Parameter-Efficient Fine-Tuning）等技术，模型可以快速适应新的类别，同时不忘记旧的知识。

下表总结了部分典型算法在泛化能力和鲁棒性方面的特点：

| 方法 (Method) | 输入模态 (Input Modality) | 鲁棒性 (Robustness) | 泛化能力 (Generalization) | 主要数据集 (Datasets) | 开源状态 (Open Source) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **OccGS**  | Vision-Centric | Open-Vocabulary | Zero-Shot | SemanticKITTI | Yes |
| **TEOcc**  | Multi-Modal (Radar+Camera) | Weather-Robust (via Radar) | Closed-Set | nuScenes | No |
| **SurroundOcc**  | Vision-Centric | Out-of-Distribution Robust (via Augmentation) | Closed-Set | nuScenes | Yes |
| **BEVFusion**  | Multi-Modal (LiDAR+Camera) | Sensor-Failure-Robust (Limited) | Closed-Set | Waymo | No |

## 6. 应用与生态：模型的落地与开源

一个优秀的3D Occupancy感知算法不仅要在学术基准上取得高分，更要能够融入实际的自动驾驶系统，并在一个开放、协作的社区生态中不断迭代。本章节将探讨Occupancy感知模型的下游应用、支撑其发展的数据集生态以及代码开源的现状。

### 6.1 下游应用 (Downstream Application)

3D Occupancy感知作为一种通用、细粒度的三维场景表示，为自动驾驶的多个下游任务提供了强大的基础。

#### 6.1.1 感知任务 (Perception Tasks)

*   **语义分割 (Semantic Segmentation)** ：Occupancy预测本身就是对三维空间进行体素级的语义分割，这是其最直接的应用。相比于传统的基于物体检测的方法，Occupancy表示能够处理任意形状的物体，更好地捕捉场景的几何细节，尤其对于检测“字典外”（Unknown）的障碍物至关重要。
*   **3D物体检测 (3D Object Detection)** ：Occupancy网格可以作为3D物体检测的输入或辅助信息。例如，可以先通过Occupancy预测得到场景的密集几何表示，然后在此基础上进行实例分割和物体检测，这有助于解决远距离或小物体的检测难题。
*   **动态感知 (Dynamic Perception)** ：通过引入时序信息，Occupancy模型可以预测场景中每个体素的运动状态（即Occupancy Flow），从而实现对动态物体的速度、方向等信息的估计。这对于自动驾驶车辆的轨迹预测和规划至关重要。

#### 6.1.2 集成层级 (Integration Level)

*   **感知-预测 (Perception-Prediction)** ：Occupancy感知可以与轨迹预测任务紧密结合。例如，**OccWorld**和**OccTENS**等“世界模型”不仅预测当前的Occupancy状态，还能根据历史信息预测未来的Occupancy场景，为车辆提供更长的决策视野 。
*   **感知-预测-规划 (Perception-Prediction-Planning)** ：这是自动驾驶系统的最终目标。Occupancy感知提供的细粒度、可行驶区域信息可以直接用于路径规划和决策。例如，规划模块可以根据Occupancy网格中的空闲区域来生成安全、平滑的行驶轨迹，避开所有占用的体素。这种端到端的集成方式，能够最大限度地减少信息损失，提升系统的整体性能和安全性。

### 6.2 数据集 (Datasets Used)

高质量、大规模的数据集是推动3D Occupancy感知技术发展的基石。近年来，研究社区构建了一系列专门用于Occupancy预测任务的基准数据集。

#### 6.2.1 传统与专用数据集 (Traditional & Occupancy-Specific)

*   **传统数据集**：如**KITTI**、**nuScenes**和**Waymo**，这些数据集最初是为3D目标检测和跟踪等任务设计的，但它们提供了高质量的LiDAR点云和相机图像，许多Occupancy研究通过在这些数据上生成Occupancy标签来进行实验。
*   **专用Occupancy数据集**：为了更好地评估Occupancy感知能力，研究者们构建了专门的基准。
    *   **SemanticKITTI**：基于KITTI数据集，提供了稠密的点云语义分割标注，是早期Occupancy研究的重要基准。
    *   **Occ3D / OpenOccupancy**：基于nuScenes数据集构建，提供了完整的3D Occupancy标签，是目前最主流的Occupancy评估基准之一。
    *   **SSCBench / OCFBench / Cam4DOcc**：这些数据集分别针对语义场景补全、4D Occupancy预测等特定任务，提供了更具挑战性的评估场景。

#### 6.2.2 合成数据集 (Synthetic Datasets)

合成数据集通过计算机图形学技术生成，具有标注完美、场景多样、成本低廉等优点，是进行算法开发和验证的重要工具。
*   **Virtual KITTI**：基于KITTI场景合成的虚拟数据集，提供了完美的标注。
*   **CARLA**：一个开源的自动驾驶模拟器，可以生成各种复杂的交通场景和传感器数据，被广泛用于训练和测试Occupancy感知模型。

### 6.3 开源状态 (Open Source Status)

代码和模型的开源对于推动学术研究和工业应用至关重要。一个活跃的开源社区可以加速技术的迭代和创新。

*   **完全开源 (Full Open Source)** ：提供完整的训练、推理代码以及预训练模型权重。这是最理想的开源状态，允许研究者复现结果并进行二次开发。例如，**MonoScene**、**TPVFormer**、**SurroundOcc**和**OccGS**等方法都提供了完整的开源实现。
*   **部分开源 (Partial Open Source)** ：只提供部分代码（如推理代码或模型架构），但不提供完整的训练代码或预训练权重。这在一定程度上限制了研究者的使用。
*   **闭源 (Closed Source)** ：不公开任何代码或模型。这通常出现在工业界的解决方案中。
*   **研究预览 (Research Preview)** ：一些大型科技公司或研究机构可能会发布其模型的研究预览版，提供有限的API或演示，但不公开内部实现细节。

下表总结了部分典型算法的开源状态及其特点：

| 方法 (Method) | 开源状态 (Open Source) | 特点 (Features) |
| :--- | :--- | :--- |
| **MonoScene**  | Full Open Source | 单目视觉，CNN-Transformer混合架构，提供PyTorch代码和模型。 |
| **TPVFormer**  | Full Open Source | 多相机视觉，基于Transformer和三视图表示，提供PyTorch代码和模型。 |
| **SurroundOcc**  | Full Open Source | 多相机视觉，基于3D体素表示，提供PyTorch代码和模型。 |
| **BEVFusion**  | Closed Source | 多模态（LiDAR+Camera）融合，在Waymo等数据集上取得SOTA性能，但官方未开源。 |
| **OccGS**  | Full Open Source | 开放词汇，基于3D高斯表示，提供PyTorch代码和模型，支持零样本泛化。 |
